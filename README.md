# Pi Pocket Monitor

Отдельное Android-приложение на Kotlin для проверки личного сервера при
использовании телефона. Тестовая версия 0.3.0: APK собран, Android Lint прошёл в GitHub Actions.
Испытания на физическом устройстве пока не выполнены.

[Скачать APK](https://github.com/PavloYum/pi-pocket-monitor/releases/download/v0.3.0/pi-pocket-monitor-0.3.0-debug.apk)

## Возможности

- Пользователь включает foreground service с постоянным уведомлением.
- Опрос при разблокировке; затем раз в 2–30 минут, пока экран разблокирован.
- До 10 HTTP(S) endpoint, каждый независимо; успешны HTTP 2xx.
- После трёх последовательных ошибок уведомление, затем уведомление восстановления.
- Последние 100 результатов хранятся локально, без облачной аналитики.
- Проверки состояния сети телефона; отсутствие сети не объявляется отказом Pi.
- Кнопка остановки в приложении и уведомлении. Нет SSH, Telegram-токенов или
  возможности перезапуска сервера. Восстановление выполняет отдельный сервис на Pi.

Адреса не предустановлены, приватные данные пользователя не входят в репозиторий.
Для Immich укажите полный URL с `/api/server/ping`. Домашний, VPN и публичный URL
не являются автоматическими fallback: каждый внесённый URL проверяется отдельно.
Недоступность домашнего IP вне дома сама по себе не означает отказ сервера.
Для первой настройки вне дома используйте публичный endpoint либо Tailscale URL.

## Сборка

Нужны JDK 17, Android SDK Platform 35 / Build Tools 35.0.0 и Gradle 8.11.1.
Gradle wrapper пока отсутствует; установленный Gradle нужен явно.

```sh
gradle :app:assembleDebug :app:lintDebug
```

APK: `app/build/outputs/apk/debug/app-debug.apk`.
GitHub Actions выполняет ту же сборку на Ubuntu и сохраняет APK с SHA256 в artifact.
Каталог версий: [downloads](downloads/README.md).

## Проверка на телефоне

1. Установить собранный APK, указать endpoint, разрешить уведомления.
2. Включить мониторинг, убедиться в HTTP 200 в журнале.
3. Заблокировать экран: новых запросов не должно быть. Разблокировать: новая проверка.
4. Указать неработающий тестовый endpoint при доступном интернете: после трёх
   ошибок одно предупреждение; вернуть доступность — сообщение восстановления.
5. Отключить сеть телефона: отдельное сообщение, не заявление об отказе сервера.
6. Остановить мониторинг: уведомление службы исчезает, новые запросы прекращаются.

## Ограничения

Android 8+; target API 35. Foreground service specialUse объявлен в manifest.
После перезагрузки, force-stop или выгрузки Android нужно заново включить мониторинг.
Приложение не обещает непрерывную работу при ограничениях производителя.
HTTP разрешён для домашних endpoint; используйте только доверенную сеть или VPN.
TLS-проверка не отключается; редиректы не считаются здоровым endpoint.
In-flight запрос при блокировке может завершиться, но новые не запускаются,
результат после блокировки не учитывается. Уведомления требуют разрешения Android.
Проверка HTTP доступности не обнаружит все внутренние сбои приложения.
