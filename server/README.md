# Источник сводки Pi

collect.py запускается root по таймеру раз в минуту, атомарно пишет
/var/lib/pi-device-monitor/status.json (0644). Читает Docker и состояние
существующего pi-server-watch; никаких изменений контейнеров не выполняет.
serve.py запускается обычным пользователем и обслуживает только GET /status.
Перед запуском задайте PI_MONITOR_BIND равным Tailscale IPv4 этого сервера.
Не привязывать к 0.0.0.0: отдельного пароля у API нет, доступ определяется
участием в tailnet и его ACL. Доступ предоставляется устройствам tailnet,
разрешённым ACL; защиты от других доверенных участников tailnet нет.

API не публикуется через Cloudflare. Возвращает только метрики и названия/
состояния контейнеров, без env, логов приложений, токенов и личных данных.
HTTP передаётся внутри шифрованного Tailscale VPN.
При возрасте снимка свыше 180 секунд stale=true. CPU — короткий замер 0,2 с,
а не среднее за минуту. Признак running не доказывает работу бизнес-функций.
Остановленные legacy-контейнеры не выводятся; остановка важных сервисов
отображается через watched из pi-server-watch.
Проверка MQTT сейчас только по состоянию контейнера, не авторизация/публикация.

## Версия 0.4.0

services.json — явный список ожидаемых контейнеров и методов проверки. Исчезнувшие
или остановленные сервисы сохраняются в выдаче как down; старые ненужные контейнеры
в список не добавляются. Удалённый code-server пока оставлен как ожидаемый сервис
из предыдущей конфигурации; исключать только после подтверждения его удаления.
probes.py проверяет максимум 8 сервисов одновременно, HTTP/TCP timeout 3 секунды.
up означает HTTP 200 или успешный Docker healthcheck. limited — только процесс/TCP,
не доказательство работы Telegram, MQTT или TURN. Внешний домен не тестируется:
HTTP-проверки идут к внутреннему IP контейнера. Изменение Docker-сети выявляется.
Не выполняются команды восстановления или отправка тестовых сообщений ботами.
Сборщик выдаёт services с checked_at, status, method, latency_ms и detail.
Дополнительно load_average, cpu_cores, network_bytes (счётчики, не скорость).

## Версия 0.5.0 (без резервных копий)

history.py хранит метрики и инциденты 7 дней в локальной SQLite history.db (0600).
Это история мониторинга, не копии данных приложений. API получает до 120 точек
на период (час/сутки/неделя), с исходными временами и пропусками. Накопление
начинается после установки; исторические показатели не выдумываются.
Скорости сети/диска — дельты счётчиков между сборками. После перезагрузки или
сброса счётчика первая скорость отсутствует. SMART и ошибки USB/диска в kernel
journal проверяются каждые 5 минут; отсутствие инструмента/доступа даёт null.
Питание и троттлинг читаются vcgencmd; отдельно текущие и накопленные флаги.

В services.json заданы обязательные сети n8n/Immich/камеры. Камера проверяется
ffprobe с кратковременным включением захвата без записи, PostgreSQL — SELECT 1.
MQTT выполняет CONNECT без credentials, не публикует данные и не подписывается
на личные темы. При отказе авторизации MQTT остаётся limited. Полный обмен
потребует отдельного ограниченного аккаунта. Боты без heartbeat остаются limited:
проверка процесса не доказывает обработку сообщений. Клиентам сообщения не отправляются.

Режим обслуживания на Pi: sudo python3 device-monitor/maintenance.py 30
(путь относительно /home/pavel/Rpi5). 0 завершает режим, максимум 1440 минут.
HTTP API остаётся read-only: удалённого управления обслуживанием нет.
На время режима pi-server-watch пропускает восстановление и Telegram-отправки,
сбор метрик продолжается. Android подавляет оповещения по серверной сводке,
но независимые HTTP-проверки телефона продолжают работать.

Ключ постоянной APK-подписи хранится вне репозитория и в GitHub Actions secrets.
При переходе с debug 0.4.0 нужна переустановка, затем release-обновления используют
один ключ. Не удалять signing secrets или локальный keystore без плана миграции.
